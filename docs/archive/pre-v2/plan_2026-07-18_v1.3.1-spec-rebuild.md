# HAIGURE SURVIVAL v1.3.1 仕様書再構築 計画

更新日: 2026-07-18

## プロンプト
まず最新のこのハイグレサバイバルの中身を、全体的に理解して、最新の仕様で仕様書をdocs配下に作ってください。

すでにdocs配下には、`spec.md`、`spec_stage_json.md`、その他、今まで使用したプランファイルが多数置いてあります。これらを一度docsの下にディレクトリを作り、バージョン1.3.1より前の情報として新しいディレクトリへ退避させてください。そのうえで、現在の実装をもとに、仕様書とステージJSONの作り方の仕様書を作り直してください。仕様書の粒度などで迷う場合は、先に確認してください。

確認結果に基づく追加条件:

- 既存のdocs直下資料は全ファイルを退避する。
- 新しい資料は、ゲーム全体仕様、技術・アーキテクチャ仕様、ステージJSON仕様の3冊構成とする。
- 粒度は「実用＋技術概要」とし、遊び方・ルール・設定・ステージ・状態遷移を網羅し、内部構造や主要定数は保守に必要な範囲で記載する。
- 旧資料の退避先は `docs/archive/pre-v1.3.1/` とする。
- 現行v1.3.1の実装済み挙動を正とし、機械可読なJSON Schemaは新設しない。

## 結果
- 既存のdocs直下にあった全93ファイルを `docs/archive/pre-v1.3.1/` へ移動し、移動前後のSHA-256がすべて一致することを確認した。
- v1.3.1の実装、タイトル設定、ゲームフェーズ、キャラクター状態、NPC・ビットAI、光線、公開処刑、専用ステージシステム、素材読込を再調査した。
- `docs/spec.md` をゲーム全体仕様書として再作成した。
- `docs/spec_technical.md` を技術・アーキテクチャ仕様書として新規作成した。
- `docs/spec_stage_json.md` を現行 `StageJson` 型と全8ステージの実データに基づく作成仕様書として再作成した。
- 全8ステージJSONが構文解析でき、ランタイム必須のマップ、環境、物理記号、スポーン、整列領域、進行オプションを満たすことを確認した。

- 新規4文書がUTF-8（BOMなし）であり、Markdownコードフェンスと相互リンクが正常であることを確認した。
- `git diff --check` と `npm run build` を実行し、Web・Electronともにビルドが成功した。
- ゲーム実装コードとステージJSONは変更していない。
