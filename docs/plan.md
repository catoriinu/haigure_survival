# HAIGURE SURVIVAL v2 複数セッション実装ロードマップ 計画

更新日: 2026-07-20

## プロンプト

PLEASE IMPLEMENT THIS PLAN:

HAIGURE SURVIVAL v2は、大規模な一括実装を行わず、1タスク＝1セッションを基本として実装する。

- 最初に小型の「立体テストコース」をBlenderで作り、GLBとゲーム間の規約を確定する。
- 規約確定後は、エンジン改修系と学校モデル制作系を最大2系統で並行する。
- 完成した学校を先に作らず、ブロックアウト段階からゲーム内へ繰り返し取り込む。
- どのBlenderモデルでも無条件に読み込める構造は目指さず、確定したv2ステージ規約に準拠したモデルを扱う。
- V2の実行対象は当面学校だけとし、既存8ステージはV2実行経路から外す。既存8ステージは将来GLB・NavMeshへ移行して再導入する。
- V2の空間情報はGLBの3D形状、マーカー、ボリュームと、それらから生成したNavMeshを正本とする。JSON文字マップ、セル座標、セルナビゲーションは使用しない。
- PR #41以降の詳細な実行順、並行境界、ファイル所有、推奨モデルとリーズニングは`docs/plans/v2/next_tasks_plan.md`を正本とし、各タスク開始時に必ず読む。
- 学校は軽量ローポリとし、校舎1～4階、複数教室、廊下、玄関、校庭、体育館、階段、踊り場、屋上をプレイ可能にする。
- 学校の閉じた窓は、壁の実開口、薄い透明ガラス表示、移動体専用の不可視衝突を分離し、プレイヤー・NPC・ビットを止めて視線と全光線を通す。1～4階で指定した開いた／割れた窓だけはビット専用の双方向固定経路とし、プレイヤー・NPCを止めてビット・視線・全光線を通す。
- 詳細な学校の間取りは、Blender制作開始時に平面図を2～3案作り、ユーザー承認後に確定する。
- 小段差と階段には、プレイヤー、NPC、ビット、光線をすべて対応させる。
- キャラクターの2Dスプライト、ビット、Babylon.js製の光線とエフェクトは維持する。
- `.blend`とゲーム用`.glb`を両方リポジトリで管理する。
- 1080p・既定設定で60fpsを目標とする。

計画ファイルは次の規則で管理する。

1. 以前の`docs/plan.md`を`docs/archive/pre-v2/plan_2026-07-18_v1.3.1-spec-rebuild.md`へ退避する。
2. 本ロードマップを新しい`docs/plan.md`へ保存し、全体進捗の正本とする。
3. 個別タスクは`docs/plans/v2/<タスクID>/plan.md`で管理する。
4. 並列作業時は統合担当だけが`docs/plan.md`を更新し、各担当は自分の個別計画を更新する。
5. 各セッションは本ファイルと対象タスクの個別計画を読んでから開始する。
