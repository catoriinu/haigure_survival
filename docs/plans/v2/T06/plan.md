# HAIGURE SURVIVAL v2 T06 学校3Dステージ統合 計画

更新日: 2026-07-25

## プロンプト

T05-1A、T05-1B、T05-2とB03の成果を統合し、JSON文字マップやセル座標を使用せず、学校のGLB、3Dマーカー、3Dボリューム、人間用NavMesh、ビット用NavMesh bundleを接続する。プレイヤー、NPC、ビット、光線、視線、集合、警報、公開処刑を学校全域で検証する。閉じた窓では実開口、透明ガラス表示、全移動体の遮断を確認する。ビット通過窓では、プレイヤー・NPCの遮断、ビット専用`aperture`遷移、視線・全光線透過を確認する。屋外4帯、校舎各階、体育館上下段、階段`surface-route`、4F屋外帯と屋上外周の`boundary`を同じ共通Runtimeで双方向に統合し、屋上をゲーム・経路・索敵・戦闘対象として検証する。

既存8ステージはV2統合対象から外し、互換アダプターを作らない。将来、各ステージをGLBとNavMeshへ移行した時点で、学校と同じ3D資産契約へ登録する。

B02手動テストではV2学校でBGM、SE、VOICEが再生されなかった。読込失敗ではなくV2入口へ再生処理が未接続のため、既存の音量設定と再生ルールを維持してT06の学校統合で接続する。

B02屋上テストではプールの水面表示を維持し、プール内へ入っている間だけプレイヤー移動速度を通常の50%にすることを確定した。水中領域はJSONやセルではなく、B03でプール形状へ一致させる3D水Volumeを正本とする。

### 旧追加指示（2026-07-19、T05-1の2026-07-25契約で置換済み）

> 屋外Aと屋上Bを結ぶビット専用・双方向必須の固定LNK kind bit_roofをB03で設計/資産化し、T05-1で実飛行、T06で統合検証。bit_windowもLNK_*でありPRT_*は使わない。どちらも自由飛行でなく端点高い方を超えない。
>
> 依存順 B03-0＋T04-2A→B03-1→B03-2→T04-2B→T05-1→T05-2→T06→T07。

## 確定方針

- 学校用ステージJSONは作成しない。
- TypeScriptカタログはステージID、表示名、GLB URL、人間用NavMesh URL、ビット用NavMesh bundle URL、各profile IDとSHA-256、空間を持たないタイトル設定だけを保持する。
- スポーン、向き、集合地点は`MRK_*`、連続遷移領域は`VOL_*`、境界は`BND_*`、離散的な狭い開口だけは`LNK_*`を正本とする。
- 通常扉と階段は連続NavMeshで接続し、セルや手書き階段リンクへ戻さない。
- 窓58組は`LNK_*`のビット専用・双方向`aperture`として扱い、プレイヤー・NPCの経路へ公開しない。`PRT_*`と旧`bit_roof`は使用しない。
- 上下移動は`vertical`、階段は`surface-route`、屋外・屋上外周は`boundary`として資産が明示し、帯の隣接をIDや高さから推測しない。
- ビットの同一帯横移動はビット用NavMesh、帯・ゾーン変更は接続グラフ、実移動の最終権威はV1物理半径0.44m＋安全余裕0.10m＝半径0.54mの3D移動包絡とする。
- 屋上は窓対象外であるだけで、プレイ範囲、NavMesh、索敵、標的追跡、戦闘の対象から外さない。
- 学校以外の旧JSONステージ切替は受入条件に含めない。学校の再読込と資源破棄を検証する。
- 学校のBGM、移動・戦闘SE、VOICEは既存の音量設定と再生条件を正本とし、学校再読込やランタイム破棄で多重再生・イベント購読・Audio資源を残さない。
- プール水中判定は3D水Volumeへの進入・滞在・退出で行い、滞在中のプレイヤー水平移動速度を通常の50%にする。退出、再配置、タイトル復帰、ステージ再読込では通常速度へ確実に戻す。
- T04-2Bで`VOL_PoolWater`の読込、内外問い合わせ、プール底へのNavMesh到達、破棄・再読込までを先行確認済みである。T06はその確定済みVolumeを使い、水平速度50%と通常速度への復帰だけをゲーム進行へ接続する。
- プレイヤー洗脳状態の正本と`selectPlayerCompletion` APIはT05-2成果を使用し、T06で別の状態機械を作らない。`brainwash-in-progress`へ入った直後から選択を解放し、`playing`終了まで完了状態間を再選択できるV1最終実装の契約を維持する。旧アーカイブ仕様の10秒待機は導入しない。
- 実ゲーム入力はG＝`brainwash-complete-gun`、N＝`brainwash-complete-no-gun`、H＝`brainwash-complete-haigure`とする。G／Nでは移動可能、Hでは移動不可、Gでは左クリック射撃、Nでは接触妨害を既存T05-2 Runtimeへ接続する。
- 選択解放後はG／N／Hの操作案内を表示し、G状態のときだけ照準と左クリック射撃案内を表示する。状態変更時はプレイヤー表示とVOICEを同期し、V1に存在しない選択専用SEは追加しない。
- G／N／Hのkeydown、左クリック、VOICE、操作案内の購読は学校Runtimeの開始・破棄単位で所有し、タイトル復帰または再読込後に重複させない。

## 実行単位と推奨設定

- 推奨ブランチ: `codex/v2-t06-school-integration`
- 推奨モデル: GPT-5.6 Sol
- 推奨リーズニング: Ultra
- 理由: B03最終資産、T04複数階NavMesh、T05戦闘、音声、水中、学校全域、資源ライフサイクルを一つの実ゲームへ統合するため。
- 代替: GPT-5.6 Sol / Extra High。単一の既知不具合修正だけならHighへ下げてよい。
- 開始条件: B03-2、T04-2B、T05-1、T05-2が`develop`へマージ済みであること。他の成果ブランチと並行実装しない。依存順は`B03-0＋T04-2A → B03-1 → B03-2 → T04-2B → T05-1 → T05-2 → T06 → T07`とする。T05-1AとT05-1Bは単一のT05-1統合成果に含める。

## 結果

本体は未着手。2026-07-19の方針変更により、学校用v2 JSONと既存8ステージ双方向切替を受入条件から削除した。学校GLB／人間用NavMesh、TypeScriptカタログ、`StageSpatialContext`、通常プレイヤー・NPC・ビット・通常ビームはT04で先行統合済みである。T05-1は別ビットNavMesh bundleと接続グラフへ更新し、旧`bit_roof`を廃止して屋上外周`boundary`へ置換する。T06は、B03の閉じた窓、58窓`aperture`、屋外・校舎・体育館・階段・屋上の全飛行帯、T05-1Bの全モード共通飛行安全、T05-2の特殊光線と全ゲームシステム、学校全域、音声、性能、最終資源ライフサイクルを統合検証する。2026-07-25のV1差分監査により、状態選択APIはT05-2実装済み、G／N／H入力・状態別案内・照準・VOICE・入力購読はT06未完了範囲であることを確定し、具体的な受入項目へ追加した。
