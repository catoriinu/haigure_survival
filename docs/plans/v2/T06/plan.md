# HAIGURE SURVIVAL v2 T06 学校3Dステージ統合 計画

更新日: 2026-08-08

## プロンプト

T05-1A、T05-1B、T05-2、T05-2V、B03、B03-3、B04、T04-3、T05-3の成果を統合し、JSON文字マップやセル座標を使用せず、学校のGLB、3Dマーカー、3Dボリューム、人間用NavMesh、ビット用NavMesh bundleを接続する。プレイヤー、NPC、ビット、光線、視線、集合、警報、公開処刑、動的扉、エレベーター、荒れた教室、NPC指示を学校全域で検証する。閉じた窓では実開口、透明ガラス表示、全移動体の遮断を確認する。ビット通過窓では、プレイヤー・NPCの遮断、ビット専用`aperture`遷移、視線・全光線透過を確認する。屋外4帯、校舎各階、体育館上下段・屋上、階段`surface-route`、4F屋外帯と屋上外周の`boundary`を同じ共通Runtimeで統合する。B04最終契約に従い、塀外のBIT飛行帯・BIT経路・スポーンは追加しない。

既存8ステージはV2統合対象から外し、互換アダプターを作らない。将来、各ステージをGLBとNavMeshへ移行した時点で、学校と同じ3D資産契約へ登録する。

B02手動テストではV2学校でBGM、SE、VOICEが再生されなかった。読込失敗ではなくV2入口へ再生処理が未接続のため、既存の音量設定と再生ルールを維持してT06の学校統合で接続する。

B02屋上テストではプールの水面表示を維持し、プール内へ入っている間だけプレイヤー移動速度を通常の50%にすることを確定した。水中領域はJSONやセルではなく、B03でプール形状へ一致させる3D水Volumeを正本とする。

## 確定方針

- 学校用ステージJSONは作成しない。
- TypeScriptカタログはステージID、表示名、GLB URL、人間用NavMesh URL、ビット用NavMesh bundle URL、各profile IDとSHA-256、空間を持たないタイトル設定だけを保持する。
- スポーン、向き、集合地点は`MRK_*`、連続遷移領域は`VOL_*`、境界は`BND_*`、離散的な狭い開口だけは`LNK_*`を正本とする。
- 通常扉と階段は連続NavMeshで接続し、セルや手書き階段リンクへ戻さない。
- 窓58組は`LNK_*`のビット専用・双方向`aperture`として扱い、プレイヤー・NPCの経路へ公開しない。`PRT_*`と旧`bit_roof`は使用しない。
- 上下移動は`vertical`、階段は`surface-route`、屋外・屋上外周は`boundary`として資産が明示し、帯の隣接をIDや高さから推測しない。
- ビットの同一帯横移動はビット用NavMesh、帯・ゾーン変更は接続グラフ、実移動の最終権威はV1物理半径0.44m＋安全余裕0.10m＝半径0.54mの3D移動包絡とする。
- 屋上は窓対象外であるだけで、プレイ範囲、NavMesh、索敵、標的追跡、戦闘の対象から外さない。
- 学校以外の旧JSONステージ切替は受入条件に含めない。学校の再読込と資源破棄を検証する。
- 学校のBGM、移動・戦闘SE、VOICEは既存の音量設定と再生条件を正本とし、学校再読込やランタイム破棄で多重再生・イベント購読・Audio資源を残さない。
- プール水中判定は3D水Volumeへの進入・滞在・退出で行い、滞在中のプレイヤー水平移動速度を通常の50%にする。退出、再配置、タイトル復帰、ステージ再読込では通常速度へ確実に戻す。
- T04-2Bで`VOL_PoolWater`の読込、内外問い合わせ、プール底へのNavMesh到達、破棄・再読込までを先行確認済みである。T06はその確定済みVolumeを使い、水平速度50%と通常速度への復帰だけをゲーム進行へ接続する。
- プレイヤー洗脳状態の正本と`selectPlayerCompletion` APIはT05-2成果を使用し、T06で別の状態機械を作らない。`brainwash-in-progress`へ入った直後から選択を解放し、`playing`終了まで完了状態間を再選択できるV1最終実装の契約を維持する。旧アーカイブ仕様の10秒待機は導入しない。
- 実ゲーム入力はG＝`brainwash-complete-gun`、N＝`brainwash-complete-no-gun`、H＝`brainwash-complete-haigure`とする。G／Nでは移動可能、Hでは移動不可、Gでは左クリック射撃、Nでは接触妨害を既存T05-2 Runtimeへ接続する。
- 選択解放後はG／N／Hの操作案内を表示し、G状態のときだけ照準と左クリック射撃案内を表示する。状態変更時はプレイヤー表示とVOICEを同期し、V1に存在しない選択専用SEは追加しない。
- G／N／Hのkeydown、左クリック、VOICE、操作案内の購読は学校Runtimeの開始・破棄単位で所有し、タイトル復帰または再読込後に重複させない。
- V1実プレイと同じく、通常設定は初期1機、既定出現間隔10秒、最大25機とする。通常BITとAlert増援は最大数へ含め、カーペット僚機は含めない。
- `docs/spec.md`の「通常開始時3体」は本契約の初期1機と矛盾しているため、T06-2実装フェーズで初期1機へ同期する。開始フェーズの初回計画コミットでは仕様書を変更しない。
- T05の即時stress設定は通常テスト初期20／最大20、性能受入初期50／最大50として維持し、通常ゲームの時間増援と混同しない。`bitCount`は`initialBitCount`へ改名し、Runtimeへ必須の出現間隔・最大数を渡す。旧名互換や既定fallbackは作らない。
- 出現候補は飛行帯ごとの明示`bit_spawn` Volumeから選び、ビット用NavMesh投影、0.54m安全包絡、共通遷移グラフへの到達性を満たし、`no_enemy_spawn`、`no_enemy_enter`、`hazard`、`water`を除外する。
- プレイヤー開始候補は向き付き`MRK_PlayerSpawn_*`として複数資産化し、安全な人間用NavMesh位置、初期カメラ空間、壁・家具・水域との非干渉を満たす候補から、同じsession seedに由来する独立した開始地点用乱数列で1件選ぶ。候補0件時の旧単一地点fallbackは作らない。
- 最低候補は現1階玄関、体育館中央、体育館舞台演説台裏、2階・3階・4階の普通教室とする。安全契約を満たすトイレ、特別教室、屋上プールサイドも候補へ加える。水中、閉鎖区画、扉・家具との干渉位置は候補にしない。
- 各開始候補には`hs_role="player_spawn_exclusion"`の閉Volumeを1件だけ対応させ、Volumeの`hs_player_spawn_id`からMarkerの`hs_id`を明示参照する。名前suffix推測、`no_enemy_spawn`流用、欠落・重複・孤立時fallbackは作らない。
- プレイヤー開始候補を先に確定し、その選択結果と有効な出現禁止Volumeを初期BIT、時間増援、Alert新規生成、初期洗脳済みNPCの必須入力として渡す。未選択の候補周囲は、この動的禁止だけを理由には除外しない。
- 学校の出現可能な各飛行帯へ`VOL_BitSpawn_*`を資産化する。共通グラフから到達可能で出現を許可する帯は1件以上のVolumeで利用可能面積を覆い、Volumeがない帯を暗黙に候補から落とさない。出現させない領域は`no_enemy_spawn`、`no_enemy_enter`、`hazard`、`water`で明示する。
- NPCはBIT用Volumeを使わず、人間用NavMeshへ投影できる`VOL_NpcSpawn_*`から選ぶ。初期洗脳済みNPCを選択中の`VOL_PlayerSpawnExclusion_*`外で先に必要数生成し、残る未洗脳NPCを通常候補から生成する。全NPC間の最小距離を維持し、候補不足時に要求人数を減らすfallbackは作らず厳格エラーにする。
- ステージ全域からのランダム選択は、V1の床セル一様抽選に近い利用可能面積比例とする。帯ごと同率の校舎内優遇は採用しない。
- B04の`BND_WorldLimit`は、プレイヤー・NPC用`BND_Stage`と分離した表示・BIT・光線の最終限界として接続する。プレイヤーとNPCの再配置・領域外判定へ流用しない。
- B04最終契約に従い、外周BIT飛行帯と外周BIT経路は0件を維持する。通常探索、待機、CHASE、逃走、総当たり探索、Alert集合先、時間増援、初期出現はいずれも塀内の到達可能帯だけを使用する。
- 外周へ`player_spawn`、`npc_spawn`、`bit_spawn`が0件であること、プレイヤー・NPCの人間用NavMeshが塀外へ延びていないことを厳格に検証する。
- T05-2Vの全光線は`BND_WorldLimit`退出点で約0.2秒の非着弾フェードへ入り、壁着弾、ダメージ、Alarm、反射光球が発生しないことを実学校で確認する。最大寿命20秒は維持する。
- `brainwash-in-progress`、gun、no-gun、haigureのNPC表示をV1対応スプライトセルへ分離し、状態Snapshot、衝突、射撃、接触拘束のロジックを変更しない。
- `V2PlayerAction`の離散入力としてF＝Follow、E＝Leave、C＝扉操作を接続し、既存計画のG／N／Hと同じRuntime開始・破棄単位で購読する。keydown repeatは無視する。
- F／EはT05-3の候補queryと`requestNpcCommand()`、CはT04-3の扉候補queryと`requestDoorToggle()`へ渡し、T06で別のAI・扉状態機械を作らない。
- NPC候補は同陣営・2m以内・frustum内・視線あり、扉候補は約1m以内とし、画面中央優先のhighlightとF／E／Cの操作promptを表示する。
- `SchoolRuntimeSettings.roomDisorderLevel`へ整数0～10を必須入力として渡し、通常ゲームの既定値を2とする。タイトル画面のスライダー表示は将来タイトルUIタスクへ延期し、T06では固定既定値とテスト設定注入だけを実装する。
- B03-3／T04-3の体育館ギャラリー・屋上、西側校舎、動的扉、エレベーター、20室variantと、T05-3のFollow・Leave・同期射撃を実ゲーム入口へ接続する。
