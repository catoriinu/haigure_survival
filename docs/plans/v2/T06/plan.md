# HAIGURE SURVIVAL v2 T06 学校3Dステージ統合 計画

更新日: 2026-07-19

## プロンプト

T05-1、T05-2とB03の成果を統合し、JSON文字マップやセル座標を使用せず、学校のGLB、3Dマーカー、3Dボリューム、事前ベイクNavMeshを接続する。プレイヤー、NPC、ビット、光線、視線、集合、警報、公開処刑を学校全域で検証する。閉じた窓では実開口、透明ガラス表示、全移動体の遮断を確認する。ビット通過窓ではB03-0で承認した開放／破損表示、プレイヤー・NPCの遮断、ビットの固定経路通過を確認し、開口を塞ぐガラス表示は必須にしない。どちらの窓でも視線・全光線透過が成立することを確認する。屋外と屋上を結ぶ`bit_roof`も双方向に統合し、屋上をゲーム・経路・索敵・戦闘対象として検証する。

既存8ステージはV2統合対象から外し、互換アダプターを作らない。将来、各ステージをGLBとNavMeshへ移行した時点で、学校と同じ3D資産契約へ登録する。

B02手動テストではV2学校でBGM、SE、VOICEが再生されなかった。読込失敗ではなくV2入口へ再生処理が未接続のため、既存の音量設定と再生ルールを維持してT06の学校統合で接続する。

B02屋上テストではプールの水面表示を維持し、プール内へ入っている間だけプレイヤー移動速度を通常の50%にすることを確定した。水中領域はJSONやセルではなく、B03でプール形状へ一致させる3D水Volumeを正本とする。

### 追加確定指示（2026-07-19）

> 屋外Aと屋上Bを結ぶビット専用・双方向必須の固定LNK kind bit_roofをB03で設計/資産化し、T05-1で実飛行、T06で統合検証。bit_windowもLNK_*でありPRT_*は使わない。どちらも自由飛行でなく端点高い方を超えない。
>
> 依存順 B03-0＋T04-2A→B03-1→B03-2→T04-2B→T05-1→T05-2→T06→T07。

## 確定方針

- 学校用ステージJSONは作成しない。
- TypeScriptカタログはステージID、表示名、GLB URL、NavMesh URL、空間を持たないタイトル設定だけを保持する。
- スポーン、向き、集合地点は`MRK_*`、領域は`VOL_*`、境界は`BND_*`、設計上必要な特殊接続だけは`LNK_*`を正本とする。
- 通常扉と階段は連続NavMeshで接続し、セルや手書き階段リンクへ戻さない。
- `bit_window`は校舎1～4階それぞれ最低1か所にある`LNK_*`だけを使用し、屋上を窓対象に含めない。`bit_roof`は屋外の安全な待機位置Aと屋上の安全な着地点Bを結ぶ`LNK_*`とする。どちらにも`PRT_*`を使用しない。
- `bit_window`と`bit_roof`はビット専用・双方向必須の固定経路とし、自由飛行にはしない。経路上の最高高度は両端A/Bの高い方を越えない。
- 屋上は窓対象外であるだけで、プレイ範囲、NavMesh、索敵、標的追跡、戦闘の対象から外さない。
- 学校以外の旧JSONステージ切替は受入条件に含めない。学校の再読込と資源破棄を検証する。
- 学校のBGM、移動・戦闘SE、VOICEは既存の音量設定と再生条件を正本とし、学校再読込やランタイム破棄で多重再生・イベント購読・Audio資源を残さない。
- プール水中判定は3D水Volumeへの進入・滞在・退出で行い、滞在中のプレイヤー水平移動速度を通常の50%にする。退出、再配置、タイトル復帰、ステージ再読込では通常速度へ確実に戻す。

## 実行単位と推奨設定

- 推奨ブランチ: `codex/v2-t06-school-integration`
- 推奨モデル: GPT-5.6 Sol
- 推奨リーズニング: Ultra
- 理由: B03最終資産、T04複数階NavMesh、T05戦闘、音声、水中、学校全域、資源ライフサイクルを一つの実ゲームへ統合するため。
- 代替: GPT-5.6 Sol / Extra High。単一の既知不具合修正だけならHighへ下げてよい。
- 開始条件: B03-2、T04-2B、T05-1、T05-2が`develop`へマージ済みであること。他の成果ブランチと並行実装しない。依存順は`B03-0＋T04-2A → B03-1 → B03-2 → T04-2B → T05-1 → T05-2 → T06 → T07`とする。

## 結果

本体は未着手。2026-07-19の方針変更により、学校用v2 JSONと既存8ステージ双方向切替を受入条件から削除した。学校GLB／NavMesh、TypeScriptカタログ、`StageSpatialContext`、通常プレイヤー・NPC・ビット・通常ビームはT04で先行統合済みである。BGM・SE・VOICEは資産読込失敗ではなくV2入口への再生処理が未接続であり、既存の音量設定を含めてT06で統合する。B03で確定する3D水Volumeを使ったプール内速度50%と通常速度への復帰もT06で統合する。T06はB03の閉じた窓、1～4階の`bit_window`、屋外A・屋上B間の`bit_roof`、T05-1の全モード共通飛行安全と実飛行、T05-2の特殊光線と全ゲームシステム、学校全域、音声、性能、最終資源ライフサイクルを統合検証する。屋上は窓対象外だがゲーム・経路対象から外さず、`bit_window`と`bit_roof`は`LNK_*`によるビット専用・双方向必須の固定経路として確認する。
