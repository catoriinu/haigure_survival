# NPC・BIT標的選択とNPC巡回調整 計画

更新日: 2026-09-12

## プロンプト

```markdown
NPC・BITの標的選択と、洗脳済みNPCの移動・戦闘の優先順位を調整してください。以下は採用済みの方向性と初期値です。現在の実装を確認し、既存の作業差分を保持したうえで実装・検証してください。

1. 標的選択傾向の比率

NPC・BITとも、標的選択傾向の割り当てを次の比率へ変更してください。

- persistent：25%
- nearest-visible：75%

各個体に傾向を割り当てる既存の仕組みを維持し、標的選択のたびに抽選し直す仕様にはしないでください。個体数に対する厳密な人数割り当てではなく、割り当て確率の変更です。

それぞれの標的選択の意味や、適用される行動モードは維持してください。

2. 移動Missionより、発見した未洗脳者への攻撃・追跡を優先

現在、通常の移動Mission中は、自律的な索敵・攻撃・追跡の分岐を飛ばす処理があります。これを変更し、Mission中でも有効な未洗脳者を発見したら、Missionを一時中断して攻撃・追跡を優先してください。

- 銃ありNPCは射撃・追跡、銃なしNPCは接近・捕獲へ移れるようにする。
- 相手を見失った場合、または洗脳などで有効な標的ではなくなった場合は、Missionへ戻れるようにする。
- 中断したMissionの目的地を保持し、Missionが引き続き有効なら再開する。
- 戦闘中の標的選択にはpersistent／nearest-visibleの違いを残す。
- 明示的な命令、Alert、Alarm、捕獲中など、通常の移動Mission以外の既存優先順位は確認し、今回の変更で不用意に崩さない。

通常の徘徊には、既に発見から戦闘へ移る処理があります。徘徊の戦闘移行を新規機能として二重実装せず、既存の処理が機能することを確認してください。

3. 未洗脳者に出会えないNPCの巡回を徐々に広げる

人数や洗脳率による「終盤」の判定は設けず、洗脳済みNPCごとの無遭遇時間に応じて、近場の往復を減らし、巡回範囲を広げてください。

今回はNPCを対象とし、BITの既存探索モードの変更は含めません。

無遭遇時間の初期仕様：
- 攻撃・捕獲対象として有効な未洗脳者を視認できていない時間を計測する。
- 洗脳完了時から計測し、有効な対象を視認したら0に戻す。
- 拘束・演出などで行動できない間は加算を止める。
- 20秒未満は通常の徘徊。
- 20秒から巡回を広げ、80秒で最大にする。
- 20〜80秒の間は直線的に変化させる。

巡回方法：
- 遠距離の経路を新たに一括計算するのではなく、既存の短い移動をつなぐ。
- 既存の目的地更新時に進行方向をある程度引き継ぎ、すぐに引き返すような往復を減らす。
- 同じ方向へ進もうとする累積移動距離の目安は、無遭遇20秒で16m、50秒で32m、80秒以上で48mを上限とする。
- 距離はゲーム内の設定上のメートルとし、Runtimeの座標単位との換算を確認する。
- これは一回の経路長や、開始地点からの直線距離を指定するものではない。
- 壁や到達不能な場所に固執せず、既存の目的地選択の処理枠内で方向を変更する。
- 未洗脳者を発見したら、既存の標的選択に従って攻撃・追跡を優先する。

通常の移動Mission中はMissionの移動を使い、徘徊の目的地選択を重ねないでください。無遭遇時間は計測し、Mission終了後も相手が見つからなければ、その時間に応じた巡回へ移れるようにしてください。

秒数、距離、勾配、上限は調整可能な初期値としてまとめて管理してください。未発見の未洗脳者の現在位置を使って誘導する仕様にはしないでください。

4. 負荷を増やさないことを採用条件とする

現在、NPCが99人になると、カクカクと少しずつしか動けない現象があります。今回の調整で悪化させないことを重視してください。

- 索敵や経路計算の頻度、候補数、フレーム当たりの処理枠を増やして解決しない。
- 既存のスケジューリングと短い経路を利用する。
- nearest-visibleの割合増加による負荷も確認する。
- 呼び出し回数が同じという理由だけで、負荷が同じと判断しない。
- カクつきは、計算時間・論理更新・経路待ちを分けて確認する。描画補間だけで原因を解消したと扱わない。
- この巡回方法で別の階や遠い部屋への到達が保証されるとは扱わない。

同じ条件で変更前後を比較し、通常人数と99人の両方について、処理時間、経路計算の回数・待ち時間、実際の移動の途切れを確認してください。負荷や移動が悪化する設計を、そのまま完成として採用しないでください。

5. 検証と報告

少なくとも次を検証してください。

- 個体ごとの傾向が安定し、十分な標本で25%／75%の割り当て傾向になる。
- Mission中に有効な対象を発見すると、銃あり・銃なしNPCとも適切に戦闘へ移る。
- 見失った場合や相手が洗脳された場合、有効なMissionへ復帰できる。
- 通常徘徊からの戦闘移行と、既存の命令・Alert・Alarmなどの優先順位を壊していない。
- 無遭遇時間の開始・停止・リセット、20秒／80秒の境界、距離の勾配・上限が仕様どおり。
- 壁や行き止まりに固執せず、発見時には巡回より戦闘を優先する。
- 99人時の負荷・経路待ち・移動の途切れが悪化していない。

挙動を保証する回帰テストと、通常ゲームでの実動作確認を行ってください。結果は、コードから確認した事実、実測結果、未確認事項を分けて報告してください。

今回の依頼は実装・検証・結果記録までです。commit・push・PR操作は別途指示します。
別セッションでの修正とコンフリクトしないよう進めてください。ただし最終的にはブランチは同じにしたいです。
```
