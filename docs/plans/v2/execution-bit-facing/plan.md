# 公開処刑BITの照準方向修正 計画

更新日: 2026-09-13

## プロンプト
公開処刑の、NPCをビットが処刑時に、ビットの向いている方向が中央の処刑対象ではなく、外周にいるプレイヤーを向いていました。なのに光線は処刑対象のNPCに向かって撃たれました。
はじめから処刑対象のNPCに向いた状態でこの公開処刑モードが始まるようにしてください。
また、PCをビットが処刑時や、処刑対象が複数のときも同様になっているか確認してください。

## ステップ
- [x] 開始・リプレイ時の配置と光線の対象選択を調査する。
- [x] 各BITを光線と同じ割り当て対象のaimPositionへ向ける。
- [x] NPC単体・PC・複数対象の初期方向と実画面を検証する。
- [x] 通常ゲーム確認サーバーと素材を確認し、結果を記録する。

## 結果
開始時の向きが全BIT共通でplayer.getEyePosition()だったことが原因。光線は割り当て対象のaimPositionを使用していた。通常・即時公開処刑とリプレイで共有する配置処理を修正し、BITごとの対象割り当てを初期方向へ反映した。処刑方式・射手割り当て・会場配置は変更しない。

- `npm.cmd run typecheck:v2`、`npm.cmd run typecheck:t05`: PASS。
- `http://127.0.0.1:5180/?acceptance=school`: 324/324 PASS、fixtureのconsole・Babylon異常0。
- 実学校Runtimeの回帰テストを追加。6 BITでNPC単体、PC単体、NPC 2人、PC＋NPCを検証。開始・待機・リプレイ後の各BIT前方と担当対象への方向の内積は、全条件で0.999999999999999以上。
- PC単体は修正前も注視先がPCなので一致していた。NPC単体と、複数対象でNPCを担当するBITが影響対象。
- 通常ゲームの中庭でNPC 4人・周囲NPC 36人・10 BITの描画と光線を確認。Canvas直接クリック後にRリプレイ、マウス視点変更、左右の角度から対象へ向くBITを確認。最初の開始操作ではPointer LockのWrongDocumentErrorが出たが、Canvas直接クリック後は視点操作できた。素材読込エラーなし。
- 正本作業木から通常Viteを再起動し、ポート5175とプロセス起動元を確認。正本素材モード。BGM・SEは200/audio/mpeg、VOICEは200/audio/wav、Characterは200/image/png。Character・VOICE選択肢は空ではなく、音量も0/MUTEではない。
- 検証画像は会話内で確認し、ファイル保存・Git追加は行っていない。通常URL: `http://127.0.0.1:5175/`。サーバーは継続起動。
