# NavMesh共有辺の微小移動修正 計画

更新日: 2026-09-13

## プロンプト
このエラーが出ました。原因を特定して修正してください。

NavMesh移動拘束結果が指定水平移動距離を超えました。
actualHorizontal=0.03336698597467688, requested=0.0033000000000000004, tolerance=0.02,
from={X: 1.0583237409591675 Y: 2.7125000953674316 Z: -1.0699940919876099},
desired={X: 1.0611534669646818 Y: 2.7125000953674316 Z: -1.0716919290627487},
constrained={X: 1.024999976158142 Y: 2.7125000953674316 Z: -1.071691870689392}
呼び出し経路: CachedNavigationAgent.update → SchoolV2NpcSystem.updateNavigation → updateSearchingNpc → survivalRuntime.update → main.ts。

追加質問:
再現したこの場所でのエラーっていうのは、この場所限定での特有のエラーなんですか？ それとも同様の症状が起きうる場所は全部あり得て、でそれ全部に対する根本的修正ができるんですか？ それともこの場所に対してのみ局所的な修正になるんですか。

回答: 共有辺付近の浮動小数点境界判定に起因するため別の場所でも発生し得る。特定座標を分岐に埋め込まず、共通の移動拘束処理を修正して同じ原因へ対応する。他原因のNavMesh不具合すべての解消を意味するものではない。

- [x] 提示座標・連続移動・壁拘束・面跨ぎ・高さの回帰検証を実施する。
- [x] 通常ゲーム確認と結果記録を完了する。

## 結果
通常・荒れ両方で提示値と同じ拘束結果を再現した。始点は正しいポリゴン上にあり、終点は三角形の共有辺上。Float32の境界判定差によりmoveAlongSurfaceが隣接面のどちらにも終点を含めず、離れた外壁の点を結果として返す。NPCの所属面破損やY方向の補正ではない。
変更対象はNavigationWorldの拘束処理と回帰テスト。距離超過検査、ゲーム速度、学校資産、NavMesh生成物は変更しない。

### 修正と検証
- 同一凸ポリゴンへの投影の水平誤差が1e-6以内なら、その面の投影点を使う。高さは既存moveAlongSurfaceと同じく呼び出し側の経路補間を維持する。面外の移動は既存の移動拘束を使う。
- 報告座標で通常・荒れ両variantを検証。修正前は実移動0.03336698597467688、修正後は0.003299922719832509。要求0.0033、終点誤差8.03e-8。
- NPC経路Agentの連続移動が例外なく到着。最大1ステップ0.003299984053455917で、要求予算0.0033以内。
- 学校全体128共有辺を両方向に検査し、通常・荒れそれぞれ256方向、合計512方向がPASS。最大水平終点誤差4.71e-7。特定座標以外の境界でも検証した。
- `npm.cmd run typecheck:v2`、`npm.cmd run typecheck:t04`: PASS。
- ブラウザT04検証: 修正後118/121 PASS。変更前HEADのソースをメモリ上で読み込む比較サーバーでも115/118 PASS。同じ3失敗は「部屋variantの0・4・20室とseed再現性」「学校非窓15遷移の実飛行Agent双方向受入」「実V2NpcSystemの物理階段面への接地追従」。今回追加の3項目は全PASS。3失敗を解消済みとは扱わない。
- 壁拘束、面跨ぎ、傾斜面、Y snap、水平距離の実超過拒否を含む既存検査を維持。
- 参照: [Detourの移動拘束実装](https://github.com/recastnavigation/recastnavigation/blob/main/Detour/Source/DetourNavMeshQuery.cpp)。原因の確定はインストール済みrecast-navigation 0.43.1と正本NavMeshによる実測に基づく。
- 通常ゲーム: seed=20260913、荒れ度7、30 NPC／21人洗脳済み、正本素材、3F美術室で開始。Canvasクリック、視点変更、移動操作、NPC移動とミッション時間・BIT増援の更新を画面で確認。確認範囲でNavMesh例外・ゲーム更新停止なし。長時間安定性試験ではない。
- 初回の起動・操作でPointer LockのWrongDocumentErrorが出たが、Canvas直接クリック後の視点変更は確認できた。Character読込に約1分を要した。これらを今回のNavMesh修正による解消とは扱わない。
- 正本作業木の通常Viteをポート5175で再起動し、プロセス起動元を確認。BGM・SEはHTTP 200/audio/mpeg、VOICEは200/audio/wav、Characterは200/image/png。カタログは空でなく、音量3でMUTEではない。通常サーバーは継続起動。
- 通常URL: `http://127.0.0.1:5175/`。対象fixture URL: `http://127.0.0.1:5179/`。画像は会話内で確認し、ファイル保存していない。
