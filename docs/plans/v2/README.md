# HAIGURE SURVIVAL v2 個別計画

更新日: 2026-07-19

このディレクトリは、`docs/plan.md`のv2ロードマップを複数セッションで実行するための個別計画を管理する。

現行V2の空間契約は[V2ステージランタイム仕様書](../../spec_stage_runtime_v2.md)と[ステージ資産仕様書](../../spec_stage_assets_v2.md)を正本とする。T02計画に残るステージJSON型・共通ローダーの成果は旧方式の履歴であり、現行のT02検証は学校GLBの3D分類、空間問い合わせ、資源ライフサイクルをJSON／セル非依存で確認する。

## 運用規則

- セッション開始時に`docs/plan.md`と対象タスクの`plan.md`をUTF-8で読み込む。
- セッション開始時に`docs/branch_strategy.md`を読み、最新の`develop`から対象タスク専用ブランチを作成する。
- 1セッションでは原則として1タスクだけを扱う。
- 実装の1ステップごとに対象タスクの`plan.md`を更新する。
- 並列作業中は各担当が自分のタスク計画だけを編集する。
- 全体の`docs/plan.md`は統合担当だけが更新する。
- タスク完了時は検証結果を個別計画と全体計画の両方へ反映する。
- タスク完了後はブランチをoriginへpushし、`develop`宛てのPull Requestを作成する。

## タスク一覧

- `T00`: ロードマップ保存
- `T01`: GLB・座標・衝突規約
- `T02`: 旧ステージJSON型・共通ローダー（履歴）／現行3Dステージ分類・資源ライフサイクル検証
- `T03`: プレイヤーの高さ対応
- `T04`: `StageSpatialContext`、Recast NavMesh、高さ付きNPC・ビット移動、視線・通常ビーム
- `T05`: 固定・トラップ・動的・公開処刑光線など残るゲームシステムの完全3D統合
- `B01`: 学校の間取り
- `B02`: 学校ブロックアウト
- `B03`: 学校ローポリ仕上げ
- `T06`: 学校ステージ統合
- `T07`: 性能・回帰試験・仕様書
