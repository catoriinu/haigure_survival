# HAIGURE SURVIVAL v2 個別計画

更新日: 2026-07-26

このディレクトリは、`docs/plan.md`のv2ロードマップを複数セッションで実行するための個別計画を管理する。PR #41以降の実行順、並行境界、ファイル所有、推奨モデルとリーズニングは`next_tasks_plan.md`を正本とする。

現行V2の空間契約は[V2ステージランタイム仕様書](../../spec_stage_runtime_v2.md)と[ステージ資産仕様書](../../spec_stage_assets_v2.md)を正本とする。T02計画に残るステージJSON型・共通ローダーの成果は旧方式の履歴であり、現行のT02検証は学校GLBの3D分類、空間問い合わせ、資源ライフサイクルをJSON／セル非依存で確認する。T05-1の確定半径契約はV1実形状・被弾球0.44m＋安全余裕0.10m＝移動包絡0.54mで、上下揺れは中心位置のSweepとして扱う。

## 運用規則

- セッション開始時に`docs/plan.md`、`docs/plans/v2/next_tasks_plan.md`、対象タスクの`plan.md`をUTF-8で読み込む。
- セッション開始時に`docs/branch_strategy.md`を読み、最新の`develop`から対象タスク専用ブランチを作成する。
- 1セッションでは原則として1タスクだけを扱う。
- 実装の1ステップごとに対象タスクの`plan.md`を更新する。
- 並列作業中は各担当が自分のタスク計画だけを編集する。
- 全体の`docs/plan.md`は統合担当だけが更新する。
- タスク完了時は検証結果を個別計画と全体計画の両方へ反映する。
- タスク完了後はブランチをoriginへpushし、`develop`宛てのPull Requestを作成する。
