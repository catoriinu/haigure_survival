# T07 プレイ中HUDとデバッグ表示の調整 計画

更新日: 2026-09-06

## プロンプト

> 画面上のHUDの表示をブラッシュアップしたいのと、デバッグモードについて要望を記載します。
>
> ・プレイ中の操作説明とデバッグ用表示だけが、古いデザイン（縁無し半透明の黒枠）になっている。
> それらのCSSのデザインを、タイトル画面やミッション表示等と統一してほしい
>
> ・プレイ中のデバッグ用表示は、デバッグモード時のみ出すようにしてほしい
> ・デバッグモードではないときは、デバッグ用表示がある箇所に、操作説明の枠を出す。そして操作説明の枠を拡張して以下の2行を表示してください。
> 「NPC内訳 未洗脳者 n人  洗脳済み n人」：洗脳済みにはhit-a, b, progressを含む洗脳済み系ステートをカウントする
> 「ビット n体」：出現した時点でカウントする
>
> ・操作説明枠の表示内容について
> F,E,Cが有効な時には操作説明枠ではなく、そのターゲットに対して有効な操作が出るようになっていますよね。なので操作説明枠には記載しないでください。
>
> ・デバッグモードかどうかの切り替えは、コード上のどこかの定数でboolで行ってください。画面上からは切り替えできなくてよいです。次のテストプレイでは通常モードにしておき、コミットも通常モードでおこなってください。

直前の検証範囲の訂正:

> 加えて言えば、AIがElectronビルドしてElectron環境での試験を実行する必要もありません。今後はブラウザ上でのテストのみにしてください。

ビットの集計範囲の確認回答:

> 通常のビット数のみ（推奨：設定のビット人口と一致）

## 対象と完了条件

- T07の既存作業branchを継続し、プレイ中の操作説明とデバッグ表示を変更する。学校資産、戦闘・移動・NPC状態遷移、既存の対象F／E／C表示は変更しない。
- 通常モードはミニマップ下の従来のデバッグ表示位置に操作説明と人数を表示する。デバッグモードは同位置の詳細表示と左下の操作説明を使う。
- `src/v2/debugMode.ts`のboolean定数を切り替えの正本とし、通常モードの`false`で確認・commitする。設定画面や保存schemaへ切り替えを加えない。
- NPCの未洗脳者は既存`npcHudCounts.unbrainwashed`、洗脳済みは表示NPC総数との差から求める。これによりhit-a／hit-b／progressも含む。戦闘等の既存`brainwashedNpcCount`の意味は変えない。
- BITは出現演出の開始時点から数える既存`frame.bitCount`を使用する。ユーザー回答により、カーペット射撃の一時僚機は含めず、設定のビット人口と一致させる。
- CSSはミッション表示と同じ明るい境界線、角丸、背景、影、文字の調子へ揃える。通常画面と小画面、対象操作表示、再開始をブラウザで確認する。
- buildは`npm.cmd run build:renderer`に限定する。Electronを含むbuild・起動・試験は行わない。過去の計測は履歴として残し、今回の変更前後の性能比較には流用しない。
- ローカルcommitまで実施し、正本素材の通常ゲーム確認サーバーをポート5175で維持する。

## 結果

開始時HEADは`f86d3dd`、作業branchは`codex/v2-t07-regression-docs`、差分なし。F／E／Cは対象マーカーに表示されることをコードで確認した。NPCの既存戦闘用洗脳数はhit-a／hit-bを除くため、表示用の既存分類を使用する。

`V2_DEBUG_MODE = false`を追加し、通常時の詳細表示を非表示にした。操作説明はミニマップ下へ移動し、NPC内訳と通常BIT人口の2行を追加した。F／E／Cの常設説明を削除し、G／N／Hの解禁時表示とフェーズごとのR／Enterは維持した。両パネルの境界線、角丸、背景、影、文字をMission HUDに揃えた。非表示の詳細テキスト更新は既存QAの読取契約として維持している。

### ブラウザ確認とWeb build

- Chromium 149の通常ゲームで、通常モードは詳細非表示・操作説明が左12px／上204px、デバッグモードは詳細表示・操作説明が左下であることを確認した。デバッグ側は独立した検証contextのモジュール応答だけを`true`へ置換し、製品ソースは常に`false`を維持した。
- 既定設定のNPC50人に対する未洗脳40人／洗脳済み10人／初期BIT1体、Canvas実クリックとPointer Lock、W移動・視点変更を確認した。F／E／Cの固定説明はなく、通常ゲームの対象F／E表示が残ることも実画面で確認した。
- 通常HUDを1920×1080／1280×720／640×480／480×360で確認した。さらに設定UIでNPC30人・Player洗脳済み・増援2秒へ変更し、24人／6人の内訳、BIT1→2体、G／N／H解禁後の6行表示を確認した。
- 480×360では解禁後の6行が既存の下部操作表示と重なるため、高さ400px以下の通常操作説明だけ文字・余白を縮めた。修正後の操作説明下端305.08px、下部操作表示上端312pxで重なりなし。AIが修正後画像を確認した。401px以上とデバッグ表示にはこの調整を適用しない。
- 実Rリトライ後のBIT1体・NPC内訳、実Enterによるタイトル復帰時の両パネル非表示、Canvas実クリックによる通常HUD再開を確認した。ブラウザのconsole警告・error、pageerror、HTTPエラーは0件。
- `npm.cmd run build:renderer`はPASS。V2依存監査・型検査、Vite Web build、配布監査を通過し、ローカル音声・Character素材が配布物へ混入していない。Babylon bundleの既存サイズ警告は残る。Electron build・起動・試験は実施していない。
- 独立した静的レビューでNPC／BIT集計、modeとphaseの表示切り替え、既存診断テキスト読取、追加CSSを確認し、修正を要する新規指摘は0件だった。

詳細証拠はローカルのT07監査成果物`2026-09-06/hud-polish`に保存した。`final-browser-result.json`は基本レイアウトと両modeの確認、`counter-restart-result.json`は小画面調整後の増援・6行表示・再開始の最終結果、`unlocked-normal-480.png`は調整後の実画面である。追加runnerの初回2試行はセッション公開前に旧HUDを読んだ／再開クリックした待機条件の不備で失敗し、完了待ちを修正して再確認した。製品の再開始処理は変更していない。
