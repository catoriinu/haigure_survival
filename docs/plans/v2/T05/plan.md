# HAIGURE SURVIVAL v2 T05 3Dビット・光線・ゲームシステム統合 計画

更新日: 2026-07-19

## プロンプト

V2ではJSON文字マップとセルナビゲーションを廃止し、GLBの3D形状、3Dマーカー、3Dボリューム、NavMeshをもとにすべての処理を行う。通常索敵は距離と扇形視野に加えて3D壁・障害物による視線遮蔽を必須とし、将来窓は視線とビームだけを通す。ビットと洗脳NPCは標的への直線が障害物で塞がれる場合、NavMesh上の最短経路で扉へ回り込む。

T04で学校用`StageSpatialContext`、Recast NavMesh、NPC・ビットの基本移動、通常ビーム・視線の共通3D問い合わせを導入する。T05では、ビット固有の飛行と編隊、固定光線、トラップ光線、動的ビーム、集合、警報、公開処刑など、共通基盤へ未統合のゲームシステムを完成させる。

## 確定方針

- ビットはNavMesh経路の各点に床面相対高度を加え、壁を抜けずに扉と階段を利用する。
- 通常視認した標的は遮蔽された時点で解除する。アラート由来の標的は期限内だけ保持できるが、発射したビームは壁で停止する。
- `COL_*`は移動・ビーム・視線を遮り、`COL_ActorOnly_*`は移動とNavMeshだけを遮る。窓は後者として視線と全ビームを透過する。
- 光線判定は前フレーム位置から新位置までの連続3D線分問い合わせとし、セル、NavMesh、水平レイヤーを衝突形状の代用にしない。
- スポーン禁止、集合、警報、公開処刑などの範囲はGLB内の`MRK_*`と`VOL_*`で表し、`layerId`やセル矩形は導入しない。
- カーペット爆撃など特殊直進編隊は、進路が遮られた場合に編隊を解除し、NavMesh追跡へ移行する。
