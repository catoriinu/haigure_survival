# HAIGURE SURVIVAL v2 T05 ビット飛行安全・3D戦闘・ゲームシステム統合 計画

更新日: 2026-07-19

## プロンプト

V2ではJSON文字マップとセルナビゲーションを廃止し、GLBの3D形状、3Dマーカー、3Dボリューム、NavMeshをもとにすべての処理を行う。通常索敵は距離と扇形視野に加えて3D壁・障害物による視線遮蔽を必須とし、窓は視線と全光線を通す。ビットと洗脳NPCは標的への直線が障害物で塞がれる場合、NavMesh上の完全経路で扉や階段へ回り込む。

T04-2Bまでに学校用`StageSpatialContext`、Recast NavMesh、高さ付き経路、NPCの複数階移動、移動者別衝突、`bit_window`／`bit_roof`の特殊接続分類を統合する。T05は、ビット全モード共通の飛行高度・天井・身体安全と特殊接続の実飛行をT05-1、gun所持NPC・ビットの完成戦闘、全光線、特殊編隊、集合、警報、公開処刑をT05-2として直列に実装する。

B02手動テストでは、ビットとgun所持NPCが未洗脳NPCへ密着追尾し続け、既存の光線発射やモード変更が確認できなかった。T04の簡略追跡を完成戦闘状態とは扱わず、既存ルールを基準に索敵、接近、射程維持、射撃、標的喪失、アラート追跡の状態遷移をT05-2で復元する。

## 確定方針

### T05-1 ビット飛行安全・特殊接続

- 飛行安全は探索、通常追跡、アラート追跡、戦闘接近、カーペットを含む特殊編隊、`bit_window`／`bit_roof`遷移の全モードで共有する。T05-2が追加する戦闘モードも同じ問い合わせと制約を使用し、モード固有の別実装で迂回しない。
- 通常移動では物理床面からの飛行高度を1.0～1.8mに保つ。NavMesh高や階層IDを物理床・天井形状の代用にしない。
- 高度決定では直上の天井を優先して問い合わせる。ビットの身体、銃口、上下左右の揺れ幅を含む占有範囲と、床・天井・壁に対する0.10mの安全余裕を常に確保できる高さだけを採用する。
- 探索・追跡を含む全通常移動では、中心線だけでなく身体・銃口・最大揺れ幅と0.10m余裕を含む移動包絡を、前位置から次位置までの全区間で連続判定する。高速移動でも壁、天井、庇、窓枠を飛び越えて貫通しない。
- 1.0～1.8mの通常上限を越えられるのは、承認・資産化済みの`bit_window`または`bit_roof`固定経路を通過している間だけとする。どちらも自由飛行にはせず、経路上の最高高度は両端A/Bの高い方を越えない。
- `bit_window`は校舎1～4階それぞれ最低1か所にあるビット専用・双方向必須の`LNK_*`を使用する。屋上は窓対象外だがゲーム・経路対象であり、屋外Aと屋上Bを結ぶビット専用・双方向必須の`LNK_*`を`bit_roof`として使用する。どちらにも`PRT_*`は使用しない。
- 特殊接続の遷移中に標的を喪失した場合は、その時点から距離が近い端点へ移動して固定経路を離脱する。空中停止、自由飛行への移行、遠い端点への強制完走は行わない。
- 特殊接続を完了したビットは、exit側の`NavigationLocation`と`polygonRef`へ結び直し、接続先の物理床を基準にした通常高度1.0～1.8mへ戻す。
- カーペット3体編隊は3体それぞれについて床、直上天井、身体・銃口・揺れ、安全余裕、移動線分を個別判定する。1体でも安全条件を満たさない場合、または階段、別階移動、`bit_window`、`bit_roof`へ入る必要がある場合は編隊を解除し、3体を通常の個別経路追跡へ戻す。編隊のために窓や屋上経路の幅を拡張しない。
- 旧実装の「標的の高さに一定量を足す」「ステージ全体の最高点だけで上限を決める」高度処理は復元しない。現在地の物理床と直上天井を正本とする。

### T05-2 戦闘・全光線・ゲームシステム

- 通常視認した標的は遮蔽された時点で解除する。アラート由来の標的は期限内だけ保持できるが、発射したビームは壁で停止する。
- `COL_*`は移動・ビーム・視線を遮る。`COL_ActorOnly_*`はプレイヤー・NPC・ビットの移動だけを遮り、`COL_HumanOnly_*`はプレイヤーとNPCの移動だけを遮る。どちらの窓Colliderも視線と全光線を透過する。
- 光線判定は前フレーム位置から新位置までの連続3D線分問い合わせとし、セル、NavMesh、水平レイヤーを衝突形状の代用にしない。
- スポーン禁止、集合、警報、公開処刑などの範囲はGLB内の`MRK_*`と`VOL_*`で表し、`layerId`やセル矩形は導入しない。
- gun所持NPCとビットは標的へ密着追尾し続けず、武器ごとの射程へ入ったら移動と照準を戦闘モードへ切り替え、発射間隔に従って光線を生成する。通常視認標的を壁で見失った場合は解除し、アラート標的は期限内だけ完全経路で追跡する。
- アラート標的が壁の向こうに残っていても壁越しには発射せず、完全経路で射線の通る位置へ回り込む。経路がない場合は壁へ直進せず停止・再探索する。
- カーペット以外を含む特殊直進編隊は進路が遮られた場合に編隊を解除し、T05-1の安全制約を使う個別のNavMesh追跡へ移行する。

- [ ] ビット全モードから共用する床・直上天井・壁・身体占有範囲の問い合わせと高度決定を実装し、通常時の床上1.0～1.8m、身体・銃口・揺れ幅、0.10m安全余裕を一括して適用する
- [ ] 探索・通常追跡・アラート追跡を含む全通常移動で、前位置から次位置までの移動包絡を連続判定し、高速移動でも壁、天井、庇、窓枠を貫通しないことを検証する
- [ ] 低天井、階段、踊り場、重複床、床高の切替で直上天井を優先し、NavMeshや別階の面を床・天井形状として誤用しないことを専用fixtureで検証する
- [ ] 1～4階の`bit_window`について、屋外Aと室内Bの間をビットだけが双方向に実飛行し、プレイヤー・NPCが利用できず、固定経路の最高高度が高い端点を越えないことを検証する
- [ ] `bit_roof`について、屋外Aと屋上Bの間をビットだけが双方向に実飛行し、屋上の標的へ接近して通常範囲へ戻れ、固定経路の最高高度が高い端点を越えないことを検証する
- [ ] `bit_window`／`bit_roof`遷移中の標的喪失時に近い端点へ離脱し、空中停止や自由飛行へ移行しないことを検証する
- [ ] `bit_window`／`bit_roof`完了後にexit側の`NavigationLocation`／`polygonRef`へ結び直し、接続先の物理床基準の通常高度へ戻ることを検証する
- [ ] カーペット3体を個別の安全問い合わせへ通し、1体の天井・壁・移動線分違反、階段・別階移動・特殊接続への進入前に編隊を解除して3体を個別追跡へ戻すことを検証する
- [ ] 標的高への一定加算やステージ最高点だけの旧高度処理がなく、現在地の物理床と直上天井だけを正本にしていることを回帰検証する
- [ ] 探索、通常追跡、アラート追跡、特殊編隊と解除の全モードで同じ飛行安全制約が適用されることを実ブラウザで確認する

## 結果

T05-1、T05-2とも未着手。2026-07-19の方針変更により、旧計画のナビゲーションレイヤー、階段リンク、`layerId`、セル領域を廃止した。共通3D基盤、NPC・ビットの基本NavMesh移動、床相対高度、通常ビーム・視線遮蔽、Actor間アラート追跡、カーペット遮蔽解除はT04-1へ前倒し済みであり、高さ付き経路と特殊接続分類はT04-2A、実学校への分類統合はT04-2Bが担当する。

旧T05を、`codex/v2-t05-bit-flight-safety`で実施するT05-1と、`codex/v2-t05-combat-systems`で実施するT05-2へ分割した。T05-1は全モード共通の床上1.0～1.8m、直上天井優先、身体・銃口・揺れ幅と0.10m余裕、固定`LNK_*`だけの高度上限例外、標的喪失時の近端離脱、カーペット3体の個別判定・解除、`bit_window`／`bit_roof`の実飛行を担当する。T05-2はgun所持NPC・ビットの完成戦闘、固定・トラップ・動的ビーム、特殊編隊、集合、警報、公開処刑を担当する。T05-1を完了してからT05-2を開始し、学校全域での統合確認はT06へ引き渡す。
