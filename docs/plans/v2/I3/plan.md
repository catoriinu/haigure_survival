# HAIGURE SURVIVAL v2 I3 キャラクター表示仕上げ終了判断 計画

更新日: 2026-08-22

## プロンプト

> 鏡を常に反射させておくと負荷が大きく上がると聞きました。NPC 99人、BIT 50機を上限にしようとしている現状で、鏡の反射負荷に耐えられるか確認してください。負荷が上がりすぎるなら鏡は諦めても構いません。

> そのままI4へ連続で入り、I4用ブランチへ変更して、I3とT06-5を省略したことを書くところから始めてください。

## 目的

現行V2のCharacter表示と高負荷実測を基に、v2.0でリアルタイム鏡面反射または追加の一人称表示仕上げを実装するか判断する。採用しない場合はT06-5を機能実装なしで終了し、I4へ直接引き渡す。

## 確定判断

- v2.0ではリアルタイム鏡面反射を採用しない。`MirrorTexture`、反射専用camera、鏡面ごとのRenderTargetTexture、反射対象layer、反射設定を追加しない。
- 学校にある鏡形状は静的な装飾面として維持する。現行GLBには反射を要求する意味ノードがなく、8枚の鏡形状は既存表示batchへ含まれているため、資産変更も行わない。
- T06-1で実装済みの一人称全身表示をそのまま維持する。下向き55度からフェードインし、90度で完全表示とし、現行の描画用camera offsetも変更しない。
- 追加Runtime作業が存在しないためT06-5を省略する。T06-5用branch、worktree、実装、V3Bゲートは作成しない。
- 99 NPC／50 BITは60fps合格値ではなく、最大構成の安定性ストレス条件とする。1080p・既定設定の60fpsは別の通常構成目標としてT07へ維持する。

## 負荷根拠と受入契約

- 99 NPC、初期洗脳済み66、BIT 50の実ゲーム計測は約121.31秒で1,819 frame、実時間換算約15.0fpsだった。診断・例外は0件で完走したが、常時追加描画の余力がある状態ではない。
- 固定高負荷baselineではframe workがp95 27.1ms／p99 31.4ms、総frameがp95 33.5ms／p99 34.0msで、60fps予算16.7msを既に超えている。鏡ごとにSceneを再描画する方式は最大構成へ追加しない。
- 最大構成のT07安定性条件は、120秒完走、diagnostics・warning・error 0件、終了後の保持リーク0件、固定baselineに対する主要時間・heap指標の悪化5%以内とする。
- Character視覚受入は既存Electron確認のPASS、warning・error 0件を根拠とし、I3では新たなコード、画像、学校資産、生成器を変更しない。

## 後続への引き渡し

- I4、T06-6A～D、T07から鏡面反射と反射設定を除外する。
- T06-6Bの機能切替へ反射項目を追加しない。
- T07は基本Character画像と一人称表示を回帰するが、リアルタイム鏡面反射を性能条件へ含めない。
- I3の終了記録はI4用`codex/v2-title-settings-design`で文書化し、I4をT06-4P-2後の次タスクとして扱う。

## 結果

リアルタイム鏡面反射は最大構成の負荷余力を超えるためv2.0では不採用とした。既存の静的鏡面表現と一人称全身表示を維持し、T06-5を機能実装なしで終了した。コード、画像、学校資産、生成器、commit、push、Pull Request、レビュー、mergeは実施していない。
