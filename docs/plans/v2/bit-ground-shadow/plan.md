# BITの影の重複と高さ減衰修正 計画

更新日: 2026-09-13

## プロンプト
ビットの影について
・出現時の球状態の影（つまり円形の影）が残ったまま、円錐＋先端の球の影と被ることがあります。原因を特定して、今の形状に対する影だけになるようにしてください。
・処理が重くならないことを前提として、地面までの高さに応じて影の濃さを薄くしてください。完全リニアなグラデーションではなく、影の投射面から本体までの階ぶんの高さに応じた段階グラデーションでも構いません。

## ステップ
- [x] 影の形状切替・高さ減衰・床問い合わせを調査する。
- [x] 円形影と通常形状の影を排他的に切り替え、高さで減衰させる。
- [x] 出現・通常・下向き・強制切替・高さ・処理数を検証する。
- [x] 通常ゲームで描画を確認し、結果を記録する。

## 結果
通常状態でも下向き角度をcircleBlendへ使い、円錐＋球の影と円形影を同時表示していた。また濃さは0.22の下限により、高高度でも一定の濃さが残っていた。
今回の対象はV2 BITの投影影。NPC・Playerの影、3Dモデル、床探索頻度は変更しない。

- 出現中は円形影、完了後は円錐＋先端球の簡易影を排他表示する。公開処刑などの強制出現完了時も、その場で影を同期する。
- 濃さは `0.7 / (1 + 高さ²)` とし、投射床との距離で減衰させる。高さ0.1／0.9／1.8／2.7のvisibilityは0.693／0.387／0.165／0.084。既存の床問い合わせ結果を再利用する。
- `typecheck:v2`、`typecheck:t06` PASS。T06ブラウザ検証92/92 PASS（追加4項目を含む）。過去の公開処刑API変更が残っていた透明合成fixtureの呼び出しも現行APIへ整合した。
- 50 BIT・120更新で床問い合わせ6,000回、表示影50枚、Mesh／Material／Textureは210／6／3で増加なし。追加の床探索・テクスチャ生成はない。ゲーム全体のFPSの比較測定は行っていない。
- `http://127.0.0.1:5181/bit-shadow.html` で実BITを用いた出現球・通常・高さ別の影を正面・左右から確認。円形影の重複なし、高さに応じた減衰を目視確認した。
- 正本の通常ゲーム `http://127.0.0.1:5175/?seed=20260913` で公開処刑の10 BIT、Character表示、視点・移動操作を確認した。自動操作環境ではPointer Lock要求エラーが発生したが、Canvas操作で視点変化と移動を確認できた。高さ別の影の判別は上記専用画面で実施した。
- ポート5175は正本Viteのプロセスを確認して再起動し、起動を継続。正本BGM／SE／VOICE／Character画像のHTTP 200とaudio/mpeg・audio/wav・image/pngを確認。Character・VOICEカタログは非空、音量は各5、素材読込エラーなし。
